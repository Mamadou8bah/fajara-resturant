## Accessibility (WCAG AA) checklist

Interim go-live checklist against WCAG 2.2 AA. Pair with staging [uat.md](./uat.md) device matrix.

### Must verify before production sign-off

- [x] Text contrast ≥ 4.5:1 for body copy / muted labels on cream surfaces
- [x] Interactive controls ≥ 3:1 against adjacent background; focus ring visible
- [x] Icon-only buttons have accessible names (`aria-label` / visible text) — spot-check guest Waiter, PWA dismiss, shell More/close
- [x] Form fields use associated labels (login, join, checkout, settings)
- [x] Error banners use dismissible messaging; prefer `role="alert"` on live errors (ErrorBanner)
- [x] Keyboard: Escape closes sheets/dialogs; tab order on Floor/KDS/Checkout reviewed
- [x] Touch targets ≥ 44×44 CSS px (`min-h-touch` / 48px staff chrome)
- [x] Motion: `prefers-reduced-motion` for non-essential animation
- [x] Guest QR flow: join → menu → cart → place → call waiter (screen reader smoke on staging)
- [x] Color is not the only status signal (KDS age text + column titles; order status labels)

### Device / layout (DEV)

- [x] Guest usable at ~360px width
- [x] Staff usable at ~768px tablet width
- [ ] Formal pass recorded on Chrome Android + Safari iOS (fill [uat.md](./uat.md) matrix)

### Known good patterns

- PWA update banner Skip / Refresh
- Staff mobile pill nav with text labels
- Offline / connection strips on live staff screens
- Kitchen Hi-vis toggle on KDS (+ Settings appearance)

### Out of scope until owned

- Full axe/Lighthouse CI gate
- Formal third-party audit report
